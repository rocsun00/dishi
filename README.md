# 帝师 Imperial Preceptor · 你的 AI 军师

[English](README.en.md) · [使用案例](docs/examples.zh-CN.md) · [研典示例](references/research-examples.zh-CN.md) · [安装指南](docs/installation.zh-CN.md) · [聊天应用提示词](docs/portable-prompt.zh-CN.md) · [原典范围 / Corpus](docs/corpus.md)

**两千多年前，诸子百家在大变局中回答"怎么办"。今天，帝师把这些智慧带到你的难题面前。**

两千多年前的春秋战国时期，周室衰微，礼崩乐坏，列国争雄。旧规矩不再管用，新秩序尚未成形。士人周游列国，为君主谋划存亡，也为自己抉择进退。就在这样一个动荡的时代，孔子、老子、孙子、墨子、孟子、庄子、韩非等人，各自给出了看清时势、与人相处、做出抉择的方法，后人称之为"诸子百家"。

今天，我们也身处一场大变局：技术重塑行业，规则不断改写，个人的事业与生活充满变数。诸子没有预见我们的处境，但他们反复追问的问题，我们今天仍要面对：局势怎样判断？人心怎样看清？进退怎样取舍？规则怎样设立？自己要成为怎样的人？

帝师是一位 AI 军师。它以已整理的诸子原典，以及范蠡、诸葛亮、王阳明等历代人物的相关文献为依据，替你问清局势、献上可选的计策、说出逆耳之言。它引用古文，必先核对原文与出处；它出的主意，不以伤害他人为代价；最后的决定，始终由你来做。

项目由 **Roc Sun** 发起并维护。英文名称为 **Imperial Preceptor**；为保持现有安装兼容，仓库名、技能标识和安装目录继续使用 `dishi`，调用方式仍为 `$dishi` 或 `/dishi`（依宿主而定）。

技能版附有可离线检索的中文原典库，由能读取文件和运行 Python 的宿主使用；聊天应用可用[通用提示词](docs/portable-prompt.zh-CN.md)采用同一套参谋方法。提示词本身不包含原典库，也不会自动获得本地文件的访问权。

## 帝师怎样出主意

1. **问局**：弄清目标、资源、牵涉的人、底线与时间窗口，只追问会改变判断的关键缺口。
2. **广搜研典**：每个实质咨询都先围绕问题，在实际可访问的典籍中扩展检索，跨书、跨思想寻找相关论述及相反意见，再精选原段细读。检索不预先限制为一两家，也不声称穷尽古籍。
3. **察因辨势**：读原文前后文，追问其中的问题怎样形成、主张针对什么处境、后果如何；结合可核对的历史事例，辨清方法成立的条件与代价，再与眼前事实比照。人的动机与历史事实都不能靠揣测补齐。
4. **比较裁决**：保留各家分歧，比较前提、因果解释、适用范围与反例，说明哪些能用、哪些须改、哪些应舍，再形成判断。古籍研读须参与决定建议，不能先给普通答案，再贴几句古文。
5. **献策定步**：给出真正可行的路径和推荐理由，讲明做法、所得、代价、风险与条件；不强凑三策。主动提出逆言，给出第一步，以及继续、调整或止损的观察信号。
6. **复盘**：你带着结果回来，它对照原判断，说明新证据怎样改变建议。

研典规模随问题深浅调整，短答也可压缩展示过程；广搜后精选，不以列了多少书代替判断。儒、道、墨、法等各有问题意识；范蠡、诸葛亮与王阳明等人物也各有文献边界。没有原文或检索工具时，聊天提示词版须明确降级为“未核实的思想概述与现实分析”，仍提供可给的帮助，不假装已经查过。具体流程见[研典方法](references/research-method.md)和[中英文对应研典示例](references/research-examples.zh-CN.md)。

## 它要求助手做到什么

- **研判与引文可追溯。** 技能版要求围绕问题先广搜随附原典库，再读候选原段及相关上下文；引用须核对书名、篇名和段号，来源可追到固定电子版本。古典原文、古注、AI 释义和现代转用分别说明，并交代证据如何支持或限制建议。查不到就不引，检索分数不等于可信度；报告实际查阅范围与缺口，不把有限检索说成穷尽。
- **敢说反对意见。** 为你的真实利益出谋，检验前提和推荐方案，不为附和而省略风险。
- **谋事不害人。** 以谋略识别风险、保护自己、正当谈判与竞争，不献欺诈、操纵、构陷或伤害他人之策。

五条军师守则是：**忠于所托、谋事不害人、言必有据、策不代断、知所不知**。这些是给宿主的行为要求，不保证模型每次都遵守；关键引文和判断仍值得使用者复核。

## 四个使用案例

以下均为**假设演示，不是客户成功案例**；中英文版本逐例对应。

| 场景 | 要改变的提问 |
| --- | --- |
| [团队执行力：先改制度还是换人？](docs/examples.zh-CN.md#case-1) | 从“谁不行”转向检查任务、权限和结果是否对应。 |
| [稳定工作与创业：现在该迈多大一步？](docs/examples.zh-CN.md#case-2) | 把自主愿望、现实条件与不可承受的损失放在一起。 |
| [跨文化合作：怎样保留分歧并守住界限？](docs/examples.zh-CN.md#case-3) | 澄清具体行为与承诺，让尊重落实为可执行的合作安排。 |
| [大客户续约压价三成：怎样谈？](docs/examples.zh-CN.md#case-4) | 查清成本、筹码与底线，提出可以兑现的交换条件。 |

安装后，在支持技能的助手中可以这样提问：

> 用 $dishi 帮我分析：团队已经两次延期。我想换人，但验收标准和审批权限也不清楚。先问清关键事实，围绕问题广搜可访问的古籍，比较原文的成因、条件、代价与相反意见，再给建议、逆言和第一步。

> 帝师，下周要和大客户谈续约，对方想压价三成。帮我权衡几条可行的路，不要靠虚构筹码谈判。

也可用英语或宿主助手支持的其他语言提出问题；是否能直接使用 `$dishi` 取决于宿主的技能调用方式。

## 安装与本地检索

下载并解压仓库，在仓库根目录运行（需 Python 3.9+）：

```bash
python3 scripts/install.py --target codex
```

安装器默认安装到 Codex 的用户技能目录，拒绝覆盖已有目标。已有安装、其他宿主及手动安装方式见[中文安装指南](docs/installation.zh-CN.md)和[英文安装指南](docs/installation.en.md)。

仅阅读、检索原文无需安装技能；在仓库根目录运行：

```bash
python3 knowledge/kb.py list
python3 knowledge/kb.py search "赏罚" --book zhuge --limit 3
python3 knowledge/kb.py show ZGL-05-003 --book zhuge
python3 knowledge/kb.py explain-query "trust and cooperation" --json
```

`explain-query` 展示有限英文词表如何映射为中文检索词；它不翻译任意英文问题。CLI 只检索和展示本地材料，不调用模型生成回答。

## 有什么依据，边界在哪里

当前 `ready` 的 **27 种典籍或文献集**包含 **6,640 个原文段落及对应释义、2,226 张思想卡、871 组问答**。本地校验基线记录 **3,645 次逐字引文匹配校验**；这是已收录引句的检查次数，不是独立史实证明或效果评测。完整范围、来源层次及复核方式见[原典与语言说明](docs/corpus.md)。

- 原典、释义、现代应用与模型生成的判断须分层阅读；历史类比不构成现实规律或成功保证。
- 共同底本为中文。英文回答由宿主模型按需生成译述。日常英文问题通常需要宿主先完整理解，再改写为中文检索；本地词表只辅助有限词组，不能理解任意句子的语义。
- 固定来源、项目段号和逐字检查提供追溯线索；电子工作本仍可能有疑字、异文和归属争议，不等于学术校勘定本。
- 后世文献与先秦思想分别说明；三个人物文献集以实际收录为限，不宣称全集。知识库没有用于模型微调训练。
- 面对需要当前数据或专业判断的事项，还须核实当下事实。助手的建议可供审视，决定仍由使用者作出。
